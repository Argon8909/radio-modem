# RadioBridge

Первый браузерный прототип: вводишь текст, передаёшь его слышимым звуком, на другом устройстве принимаешь через микрофон. Интерфейс на русском. Целевые устройства — ноутбук и Android с актуальным Chrome.

Физический уровень: собственный экспериментальный **4-FSK / 25 символов/с**, непрерывная фаза, поиск начала пакета, AFC, символьная синхронизация и CRC-16. Это один рабочий профиль, а не готовые FAST/ROBUST/AUTO.

## Запуск на ноутбуке

Требуется Node.js 20 или новее. Устанавливать пакеты и собирать приложение не нужно.

```sh
npm start
```

Откройте в браузере `http://localhost:8080`. Открытие `index.html` двойным щелчком (`file://`) не поддерживается: модули, Worker и AudioWorklet требуют веб-сервер.

Для проверки без микрофона раскройте «Диагностика и проверка» и нажмите «Проверить модем без микрофона». Проверка проходит через сигнал, шум 10 dB и смещение +80 Гц. Она не доказывает исправность микрофона или акустического канала.

## Как открыть на Android

На телефоне нужен **HTTPS с доверенным сертификатом**. Обычный `http://192.168.…:8080` не разрешает доступ к микрофону. `localhost` на телефоне означает сам телефон.

Возможные варианты:

1. Разместить статические файлы приложения на своём HTTPS-хостинге, например GitHub Pages. Сборка не требуется. Секретов и серверных API в приложении нет. Не публикуйте `.git`, `.local` или приватные ключи. Автоматическая публикация в этом прототипе не настроена.
2. Локально: получить доверенный на ноутбуке и Android сертификат на локальный IP ноутбука и запустить встроенный HTTPS-сервер:

```sh
node tools/serve.mjs --host 0.0.0.0 --port 8443 --cert .local/cert.pem --key .local/key.pem
```

Оба устройства подключают к одной Wi-Fi сети. В Android открывают HTTPS-адрес ноутбука с портом 8443. Сертификат должен содержать этот IP/имя и быть доверенным на Android; один лишь самоподписанный сертификат с предупреждением этого не обеспечивает. Для локальных испытаний сертификаты можно подготовить через [mkcert](https://github.com/FiloSottile/mkcert), установив только его корневой **сертификат** на свои тестовые устройства. Закрытый ключ корневого центра не переносите. Каталог `.local/` исключён из Git и недоступен через встроенный сервер.

3. Если включена отладка по USB и на ноутбуке установлен ADB: выполнить `adb reverse tcp:8080 tcp:8080`, затем открыть `http://localhost:8080` в Chrome Android. USB здесь только доставляет страницу; сообщения передаются звуком. Потребуется сохранить USB-соединение для последующих обращений к серверу либо заранее дождаться офлайн-кэширования.

После первого открытия дождитесь в диагностике «Файлы приложения сохранены для работы без интернета». Затем страницу можно перезагружать без сети на том же устройстве, в том же профиле и по тому же адресу, пока браузер не удалил данные сайта. Для первоначальной загрузки локальная сеть достаточна, интернет не обязателен. В офлайн-кэш попадают также модули Worker и AudioWorklet.

## Обмен ноутбук ↔ Android

1. На ноутбуке выберите «Это устройство: BASE», получателя FIELD. На телефоне — FIELD, получателя BASE.
2. На принимающем устройстве нажмите «Слушать» и разрешите микрофон. Можно сначала проверить уровень, говоря рядом с микрофоном.
3. На другом устройстве введите короткое сообщение и нажмите «Передать звуком». Будут слышны тоны около 1,2–1,35 кГц. Начните со средней громкости и расстояния 20–50 см в тихой комнате. Наушники для этого акустического теста не подходят.
4. Дождитесь окончания передачи. Принятое сообщение появится в журнале с отметкой «CRC ✓». Для ответа поменяйте роли: включите «Слушать» на первом устройстве, передайте со второго.

Передача останавливает локальный приём: приложение работает по очереди. После передачи для приёма ответа нажмите «Слушать» снова. «Прервать» останавливает звук и не записывает сообщение как полностью переданное. Отметка «Звук передан» не означает доставку: ACK в этом прототипе нет.

Держите вкладку открытой на переднем плане. Запрашивается удержание экрана, если браузер его поддерживает. Эхоподавление, шумоподавление и автоусиление запрашиваются выключенными; устройство может не выполнить эти пожелания. Отражения, перегрузка, обработка звука и шум могут помешать декодированию. Уменьшайте громкость, меняйте расстояние, смотрите уровень и AFC. Встроенный измеритель показывает RMS, а не SNR или спектр.

Максимум — 96 **байт UTF-8**, примерно 48 русских букв без учёта пробелов. Полезная скорость ниже 50 бит/с из-за преамбулы и заголовка. Два ASCII-символа занимают около 3,8 секунды; предельный пакет — около 19 секунд. Страница показывает длительность перед отправкой.

## Проверки

```sh
npm test
npm run measure
```

Тесты покрывают CRC, эталонный пакет, русский текст, неизвестное начало, AFC в точках 0, ±10, ±25, ±50, ±80, ±150, ±300 Гц, AWGN, малую амплитуду, дрейф, рассогласование часов, пересчёт 44,1/48 кГц, отсутствие сигнала и восстановление после повреждённого пакета. Стенд измерений делает по 8 воспроизводимых передач для каждого из 13 смещений и выводит обнаружение, успешное декодирование, PER и ошибку AFC. Это конечные испытания, а не гарантия связи при любом шуме или расстройке.

Необязательный браузерный тест требует Playwright и Chromium. Для установки инструмента отдельно от приложения:

```sh
npm install --prefix .local/browser --cache .local/npm-cache --no-audit --no-fund playwright@1.64.1
RB_PLAYWRIGHT_MODULE="$PWD/.local/browser/node_modules/playwright/index.mjs" node tools/browser-check.mjs
```

По умолчанию используется `/usr/bin/chromium`, другой исполняемый файл задаётся переменной `RB_CHROMIUM`. В тесте применяется виртуальный микрофон с WAV, проверяются AudioWorklet, Worker, проигрывание, офлайн-перезагрузка и IndexedDB. Временные WAV и скриншот сохраняются в отдельном каталоге системного temp. Поддельный микрофон не заменяет испытания на Android и двух реальных устройствах.

## Структура

- `src/packet.js` — формат пакета и CRC, независимо от модуляции.
- `src/modem.js` — CPFSK, потоковый демодулятор, AFC и синхронизация; без DOM.
- `src/resampler.js` — потоковый пересчёт частоты с ФНЧ.
- `src/capture-worklet.js` — захват аудио, без воспроизведения микрофона в динамик.
- `src/rx-worker.js` — приём в отдельном Worker.
- `src/channel.js` — воспроизводимый шумовой канал.
- `src/app.js`, `index.html`, `style.css` — интерфейс и воспроизведение звука.
- `src/storage.js` — журнал в IndexedDB; показываются последние 100 сообщений.
- `sw.js` — кэш статического приложения для офлайн-работы.
- `docs/RB-1.md` — экспериментальная спецификация и ограничения.
- `test/vectors.json` — тестовый вектор для независимых реализаций.

При изменении файлов приложения увеличивайте версию `CACHE` в `sw.js`: текущая версия использует cache-first. Для полного сброса можно удалить данные сайта в настройках браузера; это также удалит журнал.

## Границы прототипа

В облачной среде проверены симуляция и Chromium с виртуальным аудиовводом. Физический обмен ноутбук ↔ Android, рации, FM/SSB, аппаратное PTT, аппаратная реализация и дальность ещё не проверены. Нет шлюза, Telegram, FEC, ACK, повторов, контроля занятости канала и криптографической аутентификации. Это экспериментальный акустический прототип. Ограничения радиоканала будут исследоваться следующим этапом.

Зависимостей у самого приложения нет. Используются стандартные браузерные API; Node.js нужен только для тестов и локального сервера. Необязательный Playwright — Apache-2.0, см. `docs/DEPENDENCIES.md`. MIT, Copyright (c) 2026 Arkadiy Goncharov.
