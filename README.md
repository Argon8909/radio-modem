# RadioBridge 0.2 — передача с подтверждением

Браузерный экспериментальный радиомодем для ноутбука и Android. Текст передаётся звуком через динамик и микрофон. Версия 0.2 добавляет рукопожатие, короткие блоки, выборочные повторы и постоянную очередь доставки. Внешних библиотек, серверного API и сборки у приложения нет.

Разработка находится в ветке `feature/reliable-transfer`. Прототип 0.1 остаётся в `main`. **На обеих станциях для нового обмена должна быть версия 0.2** — номер виден в шапке страницы. Приём старых пакетов 0.1 сохранён, но они не имеют подтверждений.

## Запуск

Требуется Node.js 20 или новее. После переключения на новую ветку либо распаковки её ZIP выполните в папке с `package.json`:

```sh
npm start -- --port 8081
```

На этом компьютере откройте `http://localhost:8081`. `npm install` не нужен. Другой порт позволяет испытывать новую версию отдельно от 0.1 на порту 8080: данные браузера привязаны к адресу сайта. Запуск `npm start` без параметров использует порт 8080.

Открытие `index.html` двойным щелчком (`file://`) не поддерживается: браузер ограничивает загрузку модулей и работу аудиоприложения. Теперь страница явно сообщает об этом.

## Обмен

1. На ноутбуке выберите BASE, получателя FIELD. На телефоне — FIELD, получателя BASE.
2. Нажмите **«Включить связь» на обоих устройствах**, разрешите микрофон. Не сворачивайте приложение. Начните со средней громкости и расстояния 20–50 см в тихой комнате.
3. Введите текст и нажмите «Отправить». Он сначала сохраняется в исходящей очереди, затем отправляется предложение передачи.
4. После ответа получателя идут блоки, затем запрос состояния. Повреждённые и потерянные блоки досылаются. Передача и приём переключаются автоматически.
5. «Доставлено» появляется только после подтверждения второго устройства и проверки CRC всего сообщения. Звук из динамика сам по себе не означает доставку.

Если после паузы связь восстановилась, отправитель выясняет, какие блоки уже сохранены, и продолжает. При потере окончательного подтверждения получатель отвечает «Всё принято», не создавая копию сообщения в журнале.

Действия очереди: **«Пауза»**, **«Продолжить»**, **«Изменить повторы»**. После исчерпания попыток сообщение остаётся в очереди. Отключение связи и сворачивание страницы прекращают автоматические передачи. После возвращения нажмите «Включить связь»; сохранённая очередь продолжит работу. Работа аудио/таймеров в фоне Android не обещается.

## Настройки

| Параметр | По умолчанию | Диапазон |
| --- | --- | --- |
| Полезные данные блока | 20 байт | 12, 16, 20, 24, 32 |
| Максимум блоков сообщения | 32 | 1…64 |
| Блоков до запроса подтверждения | 4 | 1, 2, 4, 8 |
| Повторных сеансов после паузы | 3 | 0…10 |
| Интервал между сеансами | 30 с | 5…3600 с |
| Коротких повторов запроса или блока | 3 | 0…5 |

Повторы считаются **сверх первой попытки**. При значении 0 автоматических повторов соответствующего вида нет. При недоступном получателе настройки по умолчанию допускают 4 запроса в каждом из 4 сеансов. После неудачного сеанса выдерживается заданная пауза плюс случайные 0…10%, чтобы уменьшить повторные одновременные передачи. Таймаут ожидания ответа — отдельная автоматически рассчитанная величина; он учитывает длительность служебного пакета и переключение аудио.

По умолчанию лимит сообщения — **640 байт UTF-8**, примерно 320 русских букв. Максимальная настройка — 2048 байт (64 × 32). UTF-8 можно разделять между блоками: декодирование выполняется после полной сборки. Счётчик показывает именно байты, количество блоков и оценку времени.

На текущей физической скорости 50 бит/с подтверждения заметно увеличивают время: сообщение в 640 байт при стандартных настройках занимает ориентировочно 7 минут без повторов. Оценка не включает очередь и дополнительные задержки обработки. Это профиль для проверки надёжного обмена, не быстрый чат.

Параметры размера фиксируются в сохранённом сообщении: новые настройки применяются к новым сообщениям. Количество отложенных повторов и интервал можно отдельно изменить у уже сохранённого сообщения. Увеличение лимита не заставляет дополнять короткий текст пустыми блоками.

## Android

Телефону необходим разрешённый браузером аудиоввод: HTTPS с доверенным сертификатом либо localhost. Варианты:

- Статический HTTPS-хостинг. Можно открыть приложение в Chrome, дождаться сообщения об офлайн-кэше и добавить ярлык/установить PWA, если браузер предлагает это действие. **GitHub Pages, настроенный на `main`, продолжает показывать 0.1** до отдельной публикации новой версии.
- USB/ADB: при работающем сервере на ноутбуке выполнить `adb reverse tcp:8081 tcp:8081`, затем открыть `http://localhost:8081` в Chrome Android. На телефоне Node.js не нужен; USB доставляет файлы, сообщения идут звуком. После кэширования приложение может открываться без сети, пока данные сайта не удалены браузером.
- Локальный HTTPS: подготовить доверенный на телефоне сертификат на IP/имя ноутбука, например с помощью [mkcert](https://github.com/FiloSottile/mkcert), и запустить:

```sh
node tools/serve.mjs --host 0.0.0.0 --port 8443 --cert .local/cert.pem --key .local/key.pem
```

Обычный HTTP по LAN-адресу ноутбука не разрешает микрофон на Android. Для локального HTTPS оба устройства подключают к одной сети; на телефон устанавливают только корневой сертификат, не закрытый ключ. Сертификат сервера должен содержать используемый IP/имя. `.local` исключён из Git и закрыт встроенным сервером.

## Хранение и обновления

Очередь, принятые блоки и завершённые входящие сообщения хранятся в IndexedDB. Блоки сохраняются до подтверждения. При перезагрузке устройства звук автоматически не запускается: включите связь вручную. Старая история журнала сохраняется при обновлении базы v1→v2. На одном адресе сайта одновременно включать связь разрешается только в одной вкладке (Web Locks в поддерживаемом браузере).

«Очистить» у журнала скрывает завершённые входящие сообщения, но сохраняет сведения о доставке для защиты от дубликатов. Исходящая очередь и незавершённые входящие сообщения сохраняются. Одновременно допускается до 32 незавершённых входящих передач; новые предложения после этого получают BUSY. Завершённые подтверждения не удаляются автоматически. Очистка всех данных сайта браузером удалит и очередь, и офлайн-кэш. Это локальное хранилище, не облачная резервная копия.

При изменении файлов нужно менять имя `CACHE` в `sw.js`. После обновления сервиса перезагрузите страницу и проверьте номер версии на обеих станциях. При откате приложения 0.1 лучше использовать отдельный адрес/порт: его код открывает старую версию базы IndexedDB.

## Проверки

```sh
npm test
npm run measure
```

Первый набор проверяет физический модем, протокол, потери, дубли, CRC, паузы, предел повторов, восстановление после перезапуска, отказ хранилища и обмен в обе стороны. Стенд `measure` сохраняет первоначальные измерения физического канала 0.1 и **не является измерением скорости/надёжности транспортного протокола 0.2**.

Необязательные браузерные проверки требуют Chromium и Playwright:

```sh
npm install --prefix .local/browser --cache .local/npm-cache --no-audit --no-fund playwright@1.64.1
RB_PLAYWRIGHT_MODULE="$PWD/.local/browser/node_modules/playwright/index.mjs" node tools/browser-check.mjs
RB_PLAYWRIGHT_MODULE="$PWD/.local/browser/node_modules/playwright/index.mjs" node tools/reliable-browser-check.mjs
RB_PLAYWRIGHT_MODULE="$PWD/.local/browser/node_modules/playwright/index.mjs" node tools/storage-browser-check.mjs
```

По умолчанию используется `/usr/bin/chromium`; другой исполняемый файл задаётся через `RB_CHROMIUM`. Вторая проверка запускает две изолированные браузерные станции, направляет сгенерированное аудио в виртуальный микрофон другой станции через Web Audio, AudioWorklet и Worker, намеренно теряет один блок и одно подтверждение. Звук идёт в реальном времени, поэтому тест занимает около двух минут. Настоящие динамики, микрофоны, Android и радиоканал этим не проверяются.

Третья проверка проверяет миграцию настоящей IndexedDB v1→v2, сохранение очереди и настроек повторов после перезагрузки, а также защиту от двойного нажатия «Отправить». Результаты стендовых проверок записаны в `docs/VALIDATION.md`.

## Структура и ограничения

- `src/modem.js`, `src/resampler.js` — физический CPFSK-модем, AFC, синхронизация и аудиопересчёт.
- `src/packet.js` — CRC-16 кадров, поддержка v1 и бинарных v2.
- `src/reliable-protocol.js` — команды, bitmap блоков, CRC-32 сообщения, параметры и оценки времени.
- `src/transport.js` — очередь, рукопожатие, выборочный повтор, возобновление и подтверждения.
- `src/storage.js` — атомарное сохранение состояния в IndexedDB.
- `src/audio-link.js`, `src/capture-worklet.js`, `src/rx-worker.js` — полудуплексное аудио и защита от собственного передатчика.
- `src/app.js`, `index.html`, `style.css` — интерфейс и управление очередью.
- `docs/RELIABLE.md` — новый протокол; `docs/RB-1.md` — исходный физический профиль и формат v1.

Избыточное кодирование FEC, адаптивная скорость, спектрограмма, внешние сервисы и аппаратное PTT пока не реализованы. CRC не отключается: ошибки исправляются повторной передачей. Заявление о причине сбоя старого прототипа на границе 47/48 байт на реальном устройстве не подтверждено; новая версия сокращает длину отдельных пакетов и умеет восстанавливать потери, но не доказывает исправление исходной DSP-проблемы. Проверять акустический и радиоканал нужно отдельно. При одновременной передаче обеих станций возможна коллизия; ограниченные повторы, случайная пауза и приоритет BASE при принятых встречных предложениях помогают разойтись, но полноценного контроля занятости канала пока нет.
