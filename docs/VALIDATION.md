# Проверки RadioBridge

## Версия 0.2 — ветка feature/reliable-transfer

Дата: 21 октября 2026. Linux, Node.js 24.19.0, Chromium 154, Playwright 1.64.1. Реального Android, акустического и радиотракта в стенде нет.

- `npm test`: 38 тестов пройдены, ошибок и пропусков нет. Включены исходные 20 тестов модема и 18 тестов транспорта. Проверена доставка 47, 48, 49, 96, 640 и 2048 ASCII-байт, UTF-8 с разделением символов между блоками, потери и повреждения, выборочная досылка, потеря окончательного подтверждения, отсутствие дубликатов, сохранение частичной передачи, паузы и пределы повторов. Отказ хранилища не приводит к отправке подтверждения; повторное включение требует успешного сохранения.
- `tools/browser-check.mjs`: самопроверка, виртуальный микрофон с WAV, AudioWorklet, пересчёт 48→8 кГц, Worker, CRC и русский текст; повторный запуск микрофона; прерванное рукопожатие остаётся в очереди без статуса доставки. После офлайн-перезагрузки доступны модули, журнал, очередь, настройки и запуск микрофона.
- `tools/reliable-browser-check.mjs`: две изолированные браузерные станции обмениваются настоящим сгенерированным аудио через виртуальные микрофоны и Web Audio. Намеренно потеряны DATA с индексом 1 и первый REPORT. Отправитель повторил CHECK, затем только отсутствующий блок; сообщение принято один раз и подтверждено. Завершённые входящее и исходящее сообщения сохранились после офлайн-перезагрузки; звук автоматически не запустился.
- `tools/storage-browser-check.mjs`: настоящая IndexedDB обновлена с v1 до v2 без потери старого журнала. Очередь, индивидуальные параметры повторов и общие настройки сохранились после перезагрузки. Двойное нажатие «Отправить» не создаёт два сообщения.

Эти проверки не устанавливают причину прежнего сбоя на границе 47/48 байт в реальном акустическом канале и не доказывают его устранение. Следующий шаг — обмен между ноутбуком и Android с версией 0.2 на обеих станциях: сначала короткий текст, затем 49/96 байт и несколько блоков с искусственным перекрытием звука. Отдельно проверить повтор после потери связи и возвращения к странице. Фоновая работа Android не гарантируется.

## Исходный прототип 0.1

Дата: 21 октября 2026. Проверки проведены в Linux cloud environment; реальных микрофона, Android и радиостанций здесь нет.

- `npm test`: 20 тестов выполнены, 20 пройдены, пропусков нет.
- `npm run measure`: 104 из 104 сообщений обнаружены и восстановлены с верной CRC в заданных сценариях. Для каждого из 13 смещений (0, ±10, ±25, ±50, ±80, ±150, ±300 Гц) выполнено 8 передач с фиксированными seed. AWGN SNR=10 dB относительно мощности активного сигнала при 8 кГц. Текст: «Привет, эфир!». PER=0 в этой выборке; средняя абсолютная ошибка финальной оценки AFC для отдельных смещений 0,045…0,125 Гц. Это результат синтетического канала с конечной выборкой, не оценка надёжности реальной связи.
- Chromium + Playwright: кнопка самопроверки, WAV как виртуальный микрофон со сдвигом +80 Гц, захват через AudioWorklet и Worker, приём русского текста с CRC, воспроизведение из интерфейса, контроль лимита UTF-8. Проверены повторное включение микрофона и прерывание передачи без записи о её завершении. Проверены мобильная ширина 393 px без горизонтального скролла, сохранение в IndexedDB, восстановление журнала/настроек и запуск микрофона после перезагрузки без сети.

Алгоритм и параметры стенда сохранены в `test/` и `tools/measure.mjs`; браузерный сценарий — `tools/browser-check.mjs`. У тестового виртуального микрофона нет акустических отражений, реального шумоподавления телефона и нелинейностей динамика. Следующий приёмочный тест — обмен BASE↔FIELD на реальных ноутбуке и Android по инструкции README, затем отдельный радиотракт.
