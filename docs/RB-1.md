# RB-1 / 4FSK-25 — экспериментальный профиль v1

Спецификация создана независимо для RadioBridge. Код, таблицы и пакетные структуры других радиомодемов не использовались. Формат пока экспериментальный: совместимость будущих версий требует явного согласования версии.

## Физический уровень

Внутренняя частота 8000 Гц, 25 символов/с, 320 отсчётов/символ. Символы 0, 1, 2, 3 соответствуют парам 00, 01, 10, 11 и частотам 1200, 1250, 1300, 1350 Гц. Старшие биты байта идут первыми. Итого 50 бит/с до накладных расходов. 50 Гц × 40 мс = 2: номинальные тоны ортогональны в символьном окне при точной синхронизации. При шуме, расстройке, рассогласовании часов и отражениях идеальная ортогональность нарушается.

TX: фаза начинается с нуля, на каждом отсчёте увеличивается на `2π f / Fs`, при смене тона сохраняется. Частота переключается ступенчато; сглаживание частотных переходов пока не применяется. Общий пакет имеет амплитудный вход/выход 5 мс. Значение амплитуды PCM 0,65; длительность тишины до/после 150/120 мс. Расстояние крайних тонов — 150 Гц, **это не измеренная занимаемая полоса**: переходы и огибающая создают боковые составляющие.

Структура передачи: `тишина → 24 символа преамбулы → 16 символов синхрослова → байты пакета → тишина`.

Преамбула (числа обозначают индексы тонов):

```text
0 3 1 0 2 1 3 2 0 1 2 3 1 3 0 2 3 2 1 0 2 0 3 1
```

Каждый тон встречается шесть раз. Последовательность содержит все тоны, переходы и нерегулярный порядок, чтобы одинаковые смещения на один межтональный интервал не принимались за перестановку символов. Свойства проверяются конечными тестами; оптимальность или специальный класс корреляционных последовательностей не заявляются. Синхрослово: `D3 91 C5 A7`, кодируется тем же отображением двух бит в тон.

## Пакет

Все многобайтовые числа — big endian. Сервисный смысл текста не относится к физическому модему.

| Байт | Содержимое |
| --- | --- |
| 0–1 | Магия `52 42` (RB) |
| 2 | Версия: 1 |
| 3 | Источник: BASE=1, FIELD=2 |
| 4 | Адресат: ALL=0, BASE=1, FIELD=2 |
| 5 | Флаги: 0, другие значения отклоняются |
| 6–7 | ID сообщения, 16 бит; не является защитой от повторов |
| 8–9 | Длина текста в байтах, 1…96 |
| 10… | UTF-8 текст |
| последние 2 | CRC-16 заголовка и текста |

CRC-16/CCITT-FALSE: полином 0x1021, init=0xffff, refin/refout=false, xorout=0. Контрольный результат для ASCII `123456789` — 0x29b1. При неверных заголовке, CRC или UTF-8 текст не выдаётся приложению. Фильтрация по адресу выполняется после проверки CRC. Широковещательный пакет принимает любой экземпляр. Адреса сейчас фиксированы, а пользователь выбирает роль устройства. Номер сообщения имеет случайное начальное значение и увеличивается; подавление дубликатов не реализовано.

Эталон для текста `RB`, BASE→FIELD, ID=1: `52420101020000010002524243cf`. Остальные параметры для генерации сигнала — `test/vectors.json`.

## Обнаружение, AFC и время

Приёмник не знает начало пакета или сдвиг. Поиск работает на окнах 320 отсчётов с шагом 80. Goertzel вычисляет мощности в сетке 900…1650 Гц с шагом 12,5 Гц. Для каждой гипотезы сдвига от −300 до +300 Гц проверяется полная известная последовательность преамбулы. Минимум 22 из 24 тонов должны выиграть сравнение, средняя доля нужного тона должна превысить 0,72, нормированная энергия — 0,12. Затем положение уточняется с шагом 8 отсчётов и частота с шагом 3,125 Гц. Эти пороги эмпирические и относятся к этому профилю.

После захвата четыре фильтра сдвигаются на оценку AFC. Дополнительные оценки мощности около выбранного тона дают ограниченную плавную коррекцию частоты. На переходах между тонами early/late-оценка ограниченно корректирует границы символа. Синхрослово должно совпасть полностью. При ошибке синхрослова, заголовка или CRC начинается новый поиск. Аудио хранится в кольцевом буфере фиксированного размера: 32768 float32, около 128 КиБ; целый пакет записывать не требуется.

Для сравнения эффектов симулятор модулирует сигнал с заданным постоянным сдвигом, линейным дрейфом в Гц/с и фактической частотой выборки. Это разные параметры. `noiseChannel` добавляет AWGN с фиксированным seed и масштабирует амплитуду. SNR определяется по мощности активного сигнала во всей дискретной полосе 8 кГц; это **не Eb/N0**. Частотно-селективные замирания, многолучёвость и импульсные помехи пока не моделируются. BER и полноценная SNR-кривая ещё не измерялись.

В браузере AudioWorklet преобразует фактическую частоту контекста (например, 44,1/48 кГц) в 8 кГц. Используется потоковый оконный sinc-фильтр с 63 коэффициентами и 128 дробными фазами. Передача использует AudioBuffer на 8 кГц с пересчётом Web Audio в частоту устройства. Программная тишина перед пакетом не заменяет аппаратную задержку PTT.

## Аппаратная перспектива

Пакет, тоны, порядок битов и тестовые векторы доступны независимо от JavaScript. Текущий приёмник **не помещается в 8 КиБ SRAM Mega**: только кольцевой буфер занимает 128 КиБ; история спектральных окон — ещё около 23 КиБ. Полный поиск требует примерно 61 × 320 × 100 ≈ 1,95 млн итераций Goertzel в секунду, до проверки шаблона. Прямой перенос на AVR 16 МГц не обоснован. Для Mega нужна отдельная реализация: фиксированная арифметика, небольшие буферы, более дешёвый грубый поиск/децимация и стендовые измерения. Тоны и формат от этого менять не обязательно.

AD9851, его обновление частоты, выходные цепи и непрерывность фазы в аппаратуре ещё не исследованы. Совместимость с Mega/AD9851 не заявляется. Ни одна из этих будущих задач не нужна для текущего браузерного прототипа.
