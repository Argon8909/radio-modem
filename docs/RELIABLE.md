# RB-1 transport v2 — экспериментальная надёжная передача

Протокол 0.2 использует неизменённый физический профиль 4FSK-25 из `RB-1.md`: преамбула, синхрослово, 50 бит/с, тоны 1200…1350 Гц. Реализация независимая. FEC пока отсутствует. Симплексный аудиотракт используется по очереди в обе стороны.

## Кадр

Общая длина заголовка — 10 байт, CRC-16 — 2 байта. Все многобайтовые поля big endian. CRC покрывает заголовок и payload. Максимальный payload кадра остаётся 96 байт, а сообщения собираются из многих кадров.

| Байты | Значение |
| --- | --- |
| 0–1 | `52 42` |
| 2 | Версия 2 |
| 3–4 | Источник и адресат: BASE=1, FIELD=2, разные; broadcast не используется |
| 5 | Тип: OFFER=1, READY=2, DATA=3, CHECK=4, REPORT=5 |
| 6–7 | Номер запроса; READY/REPORT возвращает номер соответствующего OFFER/CHECK |
| 8–9 | Длина payload (8…96) |
| 10… | Payload |
| последние 2 | CRC-16/CCITT-FALSE |

Все payload начинаются с 8-байтового ID передачи. Он случайно создаётся при добавлении в очередь и сохраняется при любых повторах и перезагрузках. Это идентификатор, не криптографическая защита. DATA использует номер запроса 0; для остальных команд номера ограничивают принятие устаревших ответов внутри одной передачи.

## Команды

**OFFER**, 17 байт payload: ID[8], размер сообщения uint16, размер блока uint8, число блоков uint8, окно uint8, CRC-32 uint32. Размер сообщения 1…2048, блок 12/16/20/24/32, число блоков 1…64, окно 1…8. Число блоков должно совпадать с округлением размера вверх. Полезные данные — UTF-8. CRC-32/ISO-HDLC: reflected polynomial `0xedb88320`, init/final XOR `0xffffffff`, check для `123456789` = `cbf43926`.

**READY / REPORT**, 22 байта payload: ID[8], состояние uint8, число блоков uint8, CRC-32 сообщения uint32, bitmap[8]. Состояния: PARTIAL=0, COMPLETE=1, UNKNOWN=2, REJECTED=3, BUSY=4. Блок i отмечается битом `(i % 8)` байта `floor(i / 8)`. COMPLETE разрешён только при полном bitmap и совпадении CRC-32/числа блоков с предложением отправителя. Для UNKNOWN/REJECTED/BUSY без известной передачи count/checksum/bitmap нулевые. READY отвечает на OFFER; REPORT — на CHECK.

**DATA**, 10…41 байт payload: ID[8], индекс блока uint8 (с нуля), 1…32 байта данных. Размер всех блоков, кроме последнего, равен размеру из OFFER. Последний имеет остаточную длину. Повторный блок заменяет соответствующий слот; завершённая передача повторно не собирается и не отображается.

**CHECK**, 8 байт payload: только ID. Получатель отвечает сохранённым bitmap, COMPLETE или UNKNOWN. Неполученный блок не мешает приёмнику ответить: CHECK явно обозначает момент смены направления.

Неподдерживаемые параметры корректного OFFER приводят к REJECTED. Пакеты с неверной CRC, адресами, типом или длиной отбрасываются без ответа: нельзя доверять их ID/номеру блока. Если ID уже существует с другими метаданными, предложение отклоняется.

## Состояния и повторы

Очередь: `queued → waiting(OFFER) → sending(DATA) → waiting(CHECK) → delivered`. По частичному bitmap отправляются только отсутствующие блоки, до размера окна. Потерянный ответ сначала вызывает повтор самого OFFER/CHECK, а не всех данных.

У каждого запроса и каждого блока в текущем сеансе ограничено число коротких повторов. По их исчерпанию сообщение переходит в `deferred`. После настраиваемой паузы новый OFFER с тем же ID узнаёт сохранённое состояние. По исчерпанию повторных сеансов — `stopped`: текст не удаляется, ручное `resume` сбрасывает счётчик отложенных сеансов. `paused` — остановка пользователем. На перезагрузке активные состояния возвращаются в `queued`; отложенные сохраняют время следующей попытки.

Короткие повторы и отложенные сеансы считаются сверх первой попытки. Настраиваемый интервал фиксирован, не экспоненциальный, плюс 0…10% случайной добавки. В ожидании используется `duration(максимальный REPORT) + 3500 мс`: запас на переключение, накопление аудио и обработку. Отсчёт начинается после завершения передачи запроса. Пауза аудиопередачи между кадрами — минимум 500 мс. Микрофон остаётся подключён, но собственный TX и следующие 150 мс не передаются в декодер. Сбросы приёмника помечаются epoch, чтобы старые события Worker не принимались за новый ответ.

Каждый вызов передатчика сериализован. При принятых одновременных предложениях BASE получает текущий сеанс, FIELD оставляет своё исходящее сообщение в очереди. Пока принимается незавершённая передача, собственная очередь ждёт; временная блокировка снимается при подтверждении завершения либо после 120 секунд без обновления. Это не полноценный CSMA: физически одновременные передачи могут обе потеряться и потребовать паузы/повторов.

## Долговечность

Состояние IndexedDB хранится отдельно по роли BASE/FIELD. Обновление снимка, в том числе завершённого текста, происходит атомарно до отправки подтверждения. Ошибка записи останавливает связь; при повторном включении состояние сначала сохраняется заново. Хранилище не является секретным или защищённым от очистки пользователем/браузером.

Получатель собирает байты по индексам, проверяет CRC-32 и декодирует UTF-8 только целиком. При несовпадении общей CRC bitmap сбрасывается, и блоки запрашиваются снова. Подтверждение доставки отличается от факта записи сообщения у отправителя: только совпадающий COMPLETE делает статус delivered. Потерянный окончательный REPORT восстанавливается запросом состояния без дубликатов.

Сведения о завершённых передачах сохраняются даже после очистки видимого журнала. Незавершённых входящих передач допускается до 32; дальнейшие предложения получают BUSY. Автоматического срока удаления сообщений/подтверждений нет. Синхронизации хранилища между устройствами нет.

В браузере связь явно включается пользователем. При сворачивании или остановке аудиоконтекста она приостанавливается. Просроченные отложенные попытки возобновляются после включения связи, а не гарантированно в фоне.

## Совместимость

v1 принимается в журнал как старый неподтверждаемый пакет; v2 для отправки требует второй станции v2. Будущий FEC/смена физического режима потребуют отдельного согласования и спецификации. Первая версия 0.1 сохранена в Git `main`, коммит `4a2337e`.
